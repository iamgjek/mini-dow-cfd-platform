# 圖表功能規格:技術指標與日盤/夜盤資訊強化

- 狀態:草稿(待實作)
- 範圍:`frontend/app.js` 圖表模組(`drawChart` 及其輔助函式)
- 相關現況:`frontend/app.js` 目前已有線圖/K線切換、日盤夜盤自動判斷(`session`/`sessionManual`)、MA5/10/20 均線、停損停利水平線、昨收線、十字線 + OHLC 提示框

## 問題陳述

目前圖表只有 MA 均線可用,而一般台股/台指期看盤軟體(XQ、群益、元大點金靈等)標配的 KD、MACD、RSI、布林通道等技術分析指標都還沒有。缺少這些指標,使用者在這個平台上做的模擬交易沒辦法練習「看指標進出場」這類最常見的台指期交易方式,平台的「練習交易」價值因此打折扣。同時,日盤/夜盤的切換雖然已經做了資料分段,但畫面上除了均價/停損停利線之外,還缺少當盤次的關鍵價位一覽(開盤價、最高/最低),不容易一眼掌握這一盤的價格範圍。

## 目標

1. 使用者可以在 K 線圖上開關 KD、MACD、RSI、布林通道,四種指標運算結果與市面上看盤軟體的預設參數(9,3,3 / 12,26,9 / 14 / 20,2)對得起來(允許小數點誤差,採相同公式與相同 K 棒資料驗證)
2. 指標一律以「目前所在的日盤或夜盤區塊」為運算範圍,不會把日盤/夜盤兩段資料混在同一次運算裡(沿用現有 `findSessionBlock` 的分段邏輯)
3. 指標開關狀態與參數設定可以跨頁面刷新保留(`localStorage`),下次打開畫面不用重新勾選
4. 新增指標不能讓現有圖表(線圖模式、MA、停損停利線、十字線提示框)的行為或效能明顯變差(60 秒內新資料到達時重繪不掉幀、不卡頓)

## 非目標(本次不做)

- **不外接台股加權指數(TAIEX)現貨報價**:使用者已確認「指數」需求就是把目前追蹤的微台指期貨本身的走勢圖表化,不需要另外串接大盤現貨指數的資料來源;`price_engine.py` 目前也只解析期貨自身的 last/bid/ask,沒有 TAIEX 代碼可用
- **不做成交量指標**:`price_engine.py` 目前只從 36 個欄位裡解析出 last(idx 12)/bid(idx 15)/ask(idx 25),沒有解析成交量欄位,且這條 feed 本質是報價 tick 而非逐筆成交,能否取得可信的成交量需要先確認 feed 內容(見「未解決問題」)
- **不做指標訊號通知/告警**(例如 KD 黃金交叉跳提醒):留待有實際需求再規劃,避免這次範圍擴大
- **不做伺服器端運算或指標歷史回測**:指標一律比照現有 MA 的做法在前端(`app.js`)用當前已載入的 K 棒資料現算,不新增後端 API 或資料表
- **不支援線圖模式(非 K 線)下顯示指標**:KD/RSI/MACD/布林通道都需要 OHLC 或至少收盤序列的固定週期取樣,只在 `chartMode === "candle"` 時可用,線圖模式維持現狀

## 使用者故事

- 身為在這個平台練習台指期交易的使用者,我想要在 K 線圖上開啟 KD/RSI,這樣我可以練習用超買超賣訊號抓進出場時機
- 身為使用者,我想要開啟 MACD 觀察柱狀圖翻紅翻綠,這樣我可以練習判斷多空動能轉換
- 身為使用者,我想要疊加布林通道,這樣我可以看價格是否觸及上下軌來判斷是否過熱/超跌
- 身為使用者,我想要指標開關設定在下次打開網頁時還記得我上次的選擇,這樣我不用每次都重新勾選
- 身為使用者,我想要指標運算不要把日盤和夜盤的資料混在一起算,這樣夜盤剛開盤時 KD/RSI 不會被日盤尾盤的雜訊拉歪

- 驗收標準:
  - Given 使用者在 K 線模式下勾選 KD,When 勾選生效,Then 主圖下方出現 KD 子圖,顯示 K 值與 D 值兩條線
  - Given 使用者切回線圖模式,When 畫面重繪,Then 指標面板與子圖全部隱藏(不允許在線圖模式顯示)

**P0-2:指標公式與預設參數**
- KD:預設 9,3,3(RSV 週期 9、K 值平滑 3、D 值平滑 3),沿用一般 KD 公式(RSV → K = 前一 K 的 2/3 + 當期 RSV 的 1/3 → D = 前一 D 的 2/3 + 當期 K 的 1/3)
- MACD:預設 12,26,9(快線 EMA12、慢線 EMA26、訊號線 DIF 的 EMA9),顯示 DIF、MACD(訊號線)兩條線 + 柱狀圖(DIF − 訊號線)
- RSI:預設週期 14,標準公式(平均漲幅 / (平均漲幅 + 平均跌幅))
- 布林通道:預設 20 週期、2 倍標準差,顯示中軌(SMA20)、上軌、下軌
- 驗收標準:抽樣一段固定 K 棒資料,用本規格公式手算或用現成金融函式庫核對,誤差在浮點精度範圍內

**P0-3:依日盤/夜盤區塊分段運算**
- 指標運算的輸入序列一律取自 `findSessionBlock(state.history, state.session).points` 建出的 K 棒陣列(與現有 `buildCandles` 邏輯相同來源),不得跨越 `blockKey` 邊界取資料
- 驗收標準:Given 夜盤剛開盤只有 5 根 K 棒,When KD/RSI 需要 9~14 根資料才有效,Then 指標在資料不足時不繪製該段(留白或不畫線),不會去抓前一個日盤區塊的資料補齊

**P0-4:指標開關與參數持久化**
- 使用者勾選的指標開關狀態存入 `localStorage`(key 例如 `chartIndicators`),頁面載入時還原
- 驗收標準:Given 使用者開啟 MACD 並重新整理頁面,When 頁面重新載入,Then MACD 子圖預設仍為開啟狀態

## 成功指標

- 定性:實際使用這個平台練習下單時,KD/MACD/RSI/布林通道四種指標都能正常開關並隨報價即時更新,不需要額外開別的看盤軟體對照
- 定量(開發驗收用,非商業指標):
  - 抽樣核對:任取一段至少 60 根 1 分 K 的歷史資料,四個指標數值與參考公式手算結果誤差 < 0.01(價格單位)
  - 效能:開啟全部四個指標後,收到新 tick 到畫面重繪完成 < 100ms(沿用現有圖表刷新的量測方式即可,不需要新增效能監控基礎設施)

## 未解決問題

- **成交量欄位是否存在**(engineering):`price_engine.py` 目前只解析 36 個欄位中的第 12/15/25 欄,其餘欄位是否包含逐筆成交量或累計成交量,需要抓一段原始 feed 內容比對欄位定義才能確定 —— 這會影響 P2 的成交量指標是否可行
- **子圖版面配置**(design):K 線圖區塊目前是單一 `<canvas id="chart">`,同時顯示主圖 + 最多 3 個指標子圖(KD/MACD/RSI)要用多個 canvas 疊放還是一個 canvas 分區域繪製,需要在動工前定案,會影響 `drawChart` 的重構範圍
- **指標開關要不要跟日盤/夜盤分開記**(stakeholder/使用者自己):例如使用者可能想日盤看 KD、夜盤看布林通道 —— 目前規格預設是同一組開關兩個盤次共用,如果需要分開記在 `localStorage` 需要另外設計 key 結構

## 時程考量

- 沒有外部截止日期,屬於自主開發的功能;建議依 P0 四個子項目(P0-1 ~ P0-4)拆成 4 個小步驟依序做完再上線,而不是一次把四個指標全部刻完才測試 —— 每個指標獨立開關,天生就適合逐一上線
